# AI 持续学习闭环 — 从「能纠正」到「越用越强」

*学习日期: 2026-05-05 | 来源: AI Agent持续学习闭环 + Hermes Agent自进化指南*

---

## 一、核心概念：「记住」≠「学会」

| 维度 | 记忆（Retrieval） | 学习（Learning） |
|------|-------------------|------------------|
| 核心机制 | 存储+检索 | 存储+分析+策略更新 |
| 失败后 | 记录"发生了什么" | 分析"为什么"+"下次如何避免" |
| 持续性 | 随时间衰减 | 随时间增强（模式提炼） |
| 行为影响 | 需主动想起 | 自动影响后续决策 |

## 二、三层记忆体系

### 第一层：事件记忆（Episodic）
记录具体发生了什么——原始数据层
```markdown
## 事件记录 2026-04-10
任务: 重构auth.py登录验证逻辑
结果: 失败（引入新bug）
表现: 登录成功率从98%降至72%
直接原因: 正则表达式覆盖了不应该覆盖的边界
```

### 第二层：模式记忆（Pattern）
从多个事件提取共同模式——因果抽象层
**触发条件**: 相同根因出现 ≥3 次
```markdown
## Pattern-001: RegexModificationWithoutTestGuard
触发条件: 修改正则/SQL/配置格式
失败形态: 修改后测试失败，原有功能被破坏
根因类型: 没有先验证原有行为就直接修改
预防策略: 修改前先写验证原有行为的测试用例
出现频率: 3次 | 置信度: 高
```

### 第三层：策略记忆（Strategic）
存储"元认知"——高层行为准则，**自动影响行为**
```markdown
## Strategic-Memory: 关于重构
- 涉及多模块交互时，先画架构图再动手
- >5文件的重构，必须先做小范围验证
- 修改正则/配置/SQL前，先写测试验证原有行为
```

### 三层关系
```
事件记忆（原始记录）
    ↓ 模式提炼（≥3次触发）
模式记忆（因果抽象）
    ↓ 策略提取
策略记忆（主动原则）→ 自动影响Agent行为
```

## 三、持续学习闭环五阶段

```
失败捕获 → 根因分析 → 模式抽象 → 策略更新 → 行为验证
    ↑                                              ↓
    └──────────────────────────────────────────────┘
```

### 阶段1：失败捕获
**来源**: 工具错误、Agent不确定标记、用户反馈、任务异常
**关键**: 立即记录，在工作上下文中捕获

### 阶段2：根因分析
四个问题:
1. 决策在哪里偏离正确方向？
2. 上下文信息是否充足？
3. 失败是能力问题还是信息问题？
4. 重新处理应在哪一步改变策略？

| 根因类型 | 处理方式 |
|----------|---------|
| 信息不足 | 补充Context，优化Schema |
| 能力不足 | 升级模型，拆解任务 |
| 误导性反馈 | 优化验证机制 |
| 系统限制 | 记录为已知限制，策略中规避 |

### 阶段3：模式抽象
- 触发条件: 相同根因 ≥3次
- 渐进式提炼，随积累逐步生成

### 阶段4：策略更新
| 注入方式 | 范围 | 持久性 |
|----------|------|--------|
| 系统Prompt注入 | 全部任务 | 持久 |
| 上下文注入 | 单次任务 | 临时 |

### 阶段5：行为验证
1. 遇到类似场景 → 注入策略提示
2. 记录Agent是否执行预防行为
3. 执行了 → 置信度+1
4. 没执行 → 分析原因，更新策略
5. 置信度低于阈值 → 触发重新分析

## 四、Hermes Agent 自进化机制

**核心创新**: 闭环学习——每次交互都在积累经验

| 维度 | 传统Agent | Hermes Agent |
|------|-----------|-------------|
| 会话记忆 | 单次会话内 | 跨会话持久化 |
| 任务经验 | 每次从零开始 | 自动生成Skill文件复用 |
| 行为优化 | 靠人工调prompt | 自动调整策略 |
| 用户建模 | 无 | 跨会话构建用户画像 |

**Skill系统**: 成功完成任务后，将关键步骤提炼为Markdown文件存入skills/目录
**混合记忆**: 长期记忆（用户偏好/项目上下文/历史决策）+ 会话记忆（临时状态）

## 五、常见陷阱

| 陷阱 | 应对策略 |
|------|---------|
| **过度记忆** | 强制阈值(≥3次)、30天清理、定期只保留Pattern |
| **模式误判** | 低置信度只在Context提示、设置衰减、定期Review |
| **策略无法执行** | 策略必须具体到可操作行为 |
| **遗忘学习** | 直接嵌入system prompt、定期Context注入 |

## 六、自动化程度分级

| 档位 | 覆盖阶段 | 适用场景 |
|------|---------|---------|
| **最小化** | 1+4 | 个人使用，快速上手 |
| **生产级** | 1-4 | 团队使用，有审计需求 |
| **企业级** | 1-5 | 大规模部署，高可靠性 |

## 七、BroadFSC 落地应用

### 立即可用改进
1. **Bot对话** → 加失败捕获：每次客户不满时自动记录事件记忆
2. **内容生成** → 加模式抽象：数据造假问题已出现多次，提炼为策略记忆
3. **邮件系统** → 加行为验证：发送后跟踪open/click，反思邮件效果
4. **全系统** → 三层记忆架构：episodic/ → patterns/ → strategic/

### 具体实现路径
```
当前: .bot_memory/emotion_profiles.json (简单键值)
  ↓
第一步: 添加 episodic/ 目录（事件记录）
  ↓
第二步: 添加 patterns/ 目录（模式提炼，≥3次触发）
  ↓
第三步: 添加 strategic/ 目录（策略记忆，自动注入system prompt）
  ↓
最终: 完整闭环——失败捕获→根因分析→模式抽象→策略更新→行为验证
```
